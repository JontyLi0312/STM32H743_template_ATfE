# STM32H743IIT6 Project Template (Based on ATfE)

A modern project template for the STM32H743IIT6, built upon the official Arm Toolchain for Embedded (ATfE), designed to be efficient, clean, and easily extensible.

## 📋 Overview

This project is a template for the STM32H743IIT6 based on the **Arm Toolchain for Embedded (ATfE)** compiler. Its initialization code is generated by STM32CubeMX and has been ported to a modern build system using **CMake** + **Clang** to provide a superior development experience.

### ✨ Features

  * **Modern Toolchain**: Based on Clang+LLVM and ATfE, freeing you from the limitations of traditional toolchains.
  * **Cross-Platform Build**: Utilizes CMake and Ninja for a consistent build experience across Windows, macOS, and Linux.
  * **VS Code Integration**: Comes with pre-configured `tasks.json` and `launch.json` for one-click compilation, flashing, and debugging.
  * **Highly Customizable**: Features a clear structure, making it easy to integrate your own application code, middleware, or RTOS.
  * **DMA Memory Optimization**: A dedicated RAM region (`.buffer` section) is pre-configured for DMA to prevent cache coherency issues.

### 🔌 Hardware Platform

  * **Board**: Fank-Tech STM32H743IIT6 minimal system board
  * **Display**: RGB interface TFT screen
  * **Pinout**: For detailed pin configurations, please refer to the `.ioc` file in the project directory, which can be opened and modified with STM32CubeMX.

## 🚀 Quick Start

The following guide will walk you through setting up the development environment and running the project. **VS Code** is highly recommended.

Please ensure the following tools are correctly installed and their paths have been added to your system's `PATH` environment variable.

### 📦 VS Code Extensions

Please install the following extensions from the VS Code Marketplace:

1.  **Cortex-Debug**: Provides debugging support for ARM Cortex-M cores.
2.  **Clangd**: For code completion, linting, and definition navigation.
3.  **CMake Tools**: For configuring, building, and managing CMake projects.

### ⚙️ Project Configuration

1.  Clone this repository to your local machine.
2.  Open the `cmake/ATfE.cmake` file.
3.  Modify the `TOOLCHAIN_PREFIX` variable to point to the actual installation path of your **ATfE** toolchain.

### 🏃‍♀️ Build and Flash

After opening the project in VS Code, press `Ctrl+Shift+B` to bring up the task list:

1.  **🧹 Clean**: Cleans up old build files.
2.  **🔨 Build**: Compiles the project (CMake configuration is run automatically on the first build).
3.  **📥 Flash (OpenOCD)**: Flashes the firmware to the target device using CMSIS-DAP via OpenOCD.
4.  **📥 Flash (PyOCD)**: Flashes the firmware to the target device via PyOCD (programmer is auto-detected).

You can also run a single, streamlined task:

  * **🚀 Clean, Build & Flash**: Automatically performs all steps: cleaning, configuring, building, and flashing (uses OpenOCD by default).

If you wish to use the `Release` preset, press `Ctrl+Shift+P` to open the command palette, type `Task: Run Task`, and select the desired `Release` task.

> All tasks are defined in the `.vscode/tasks.json` file.

## 🔬 Debugging

1.  **GDB Dependency**: The debugging feature relies on GDB from the **GNU Arm Embedded Toolchain**. Ensure this toolchain is installed and added to your system's `PATH`.
2.  **Debug Configurations**: All debug configurations are preset in the `.vscode/launch.json` file.
3.  **Start Debugging**:
      * Switch to the "Run and Debug" view in the VS Code sidebar.
      * Select `openocd_CMSIS-DAP`, `openocd_ST-Link`, or `pyOCD` from the top dropdown menu, depending on your debugger.
      * Press `F5` to start the debug session.

> **Note**: `launch.json` also includes a configuration for `probe-rs`, but it is currently unstable and not recommended for debugging. However, flashing with `probe-rs` has been verified to work.

## ⚠️ Important Note: DMA and Cache

To address cache coherency issues when **DMA** accesses peripherals, a special memory section `.buffer` has been added to the linker script (`.ld` file), located in AXI SRAM (`0x24000000`).

When you need to define a buffer for DMA, use the following attributes to place it in this specific memory region:

```c
__attribute__((section(".buffer"))) __attribute__((aligned(4))) uint8_t my_dma_buffer[1024];
```

If D-Cache is enabled, you **must** manually clean the cache after the CPU modifies this memory and before initiating a DMA transfer. This ensures that the peripheral accesses the most up-to-date data:

```c
SCB_CleanDCache_by_Addr((uint32_t*)my_dma_buffer, sizeof(my_dma_buffer));
```

## 📁 Project Structure

```
STM32H743IIT6_template_ATfE/
├── App/                # Application and business logic code
├── Core/               # Core code generated by STM32CubeMX (Inc, Src)
├── Drivers/            # HAL library and CMSIS generated by STM32CubeMX
├── User_Drivers/       # User-defined driver code (e.g., for sensors,displays)
├── cmake/              # CMake configuration files
│   └── ATfE.cmake      # ATfE toolchain definition file
├── .vscode/            # VS Code editor configuration
│   ├── launch.json     # Debug configurations
│   └── tasks.json      # Build task definitions
├── .gitignore          # Git ignore file
├── CMakeLists.txt      # Main CMake configuration file
└── STM32H743IIT6.ioc   # STM32CubeMX project file
```
