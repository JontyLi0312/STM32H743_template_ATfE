# STM32H743IIT6 Project Template (Based on ATfE)

**English** | [中文](./README.md)

A modern project template for the STM32H743IIT6, built upon the official Arm Toolchain for Embedded (ATfE), designed to be efficient, clean, and easily extensible.

## 📋 Overview

This project is a template for the STM32H743IIT6 that uses the **Arm Toolchain for Embedded (ATfE)** compiler. Its initialization code was generated by STM32CubeMX and has been ported to a modern **CMake** + **Clang** build system to provide a superior development experience.

### ✨ Features

  * **Modern Toolchain**: Based on Clang+LLVM and ATfE, freeing you from the limitations of traditional toolchains.
  * **Cross-Platform Build**: Utilizes CMake and Ninja for a consistent build experience across Windows, macOS, and Linux.
  * **VS Code Integration**: Comes with pre-configured `tasks.json` and `launch.json` for one-click compilation, flashing, and debugging.
  * **Highly Customizable**: Features a clean structure, making it easy to integrate your own application code, middleware, or RTOS.
  * **DMA Memory Optimization**: A dedicated RAM region (`.buffer` section) is pre-configured for DMA to prevent cache coherency issues.

### 🔌 Hardware Platform

  * **Board**: Fank-Tech STM32H743IIT6 Core Board
  * **Display**: RGB Interface TFT Screen
  * **Pinout**: Refer to the `.ioc` file in the project directory, which can be opened and modified with STM32CubeMX.

## 🚀 Quick Start

This guide will walk you through setting up the development environment and running the project. **VS Code** is highly recommended.

### 🛠️ Environment Setup

Ensure the following tools are correctly installed and their paths have been added to your system's `PATH` environment variable.

### 📦 VS Code Extensions

Please install the following extensions from the VS Code Marketplace:

1.  **Cortex-Debug**: For debugging ARM Cortex-M cores.
2.  **Clangd**: For code completion, syntax checking, and go-to-definition.
3.  **CMake Tools**: For configuring, building, and managing CMake projects.

### ⚙️ Project Configuration

1.  Clone this repository to your local machine.
2.  Open the `cmake/ATfE.cmake` file.
3.  Modify the `TOOLCHAIN_PREFIX` variable to point to the actual installation path of your **ATfE** toolchain.

### 🏃‍♀️ Compile and Flash

This project comes with pre-configured VS Code tasks to streamline the development process. Use the shortcut `Ctrl+Shift+B` to bring up the task panel and select the task you want to run.

Available tasks are listed below:

**Basic Tasks**: Execute a single operation.

1.  **🔧 Configure**: Configures the CMake environment. The Build task calls this automatically, so manual execution is usually not needed.
2.  **🔨 Build**: Compiles the project.
3.  **🧹 Clean**: Cleans all build-generated files.
4.  **📥 Flash (OpenOCD)**: Flashes the firmware to the target device using OpenOCD (defaults to CMSIS-DAP).
5.  **📥 Flash (pyOCD)**: Flashes the firmware to the target device using pyOCD (with any pyOCD-supported programmer).

**Composite Workflows**: Convenient workflows that execute multiple basic tasks in sequence.

1.  **🚀 Clean + Build**: Automatically completes the clean and build steps.

2.  **🚀🚀 Clean + Build + Flash (OpenOCD)**: (Recommended) A fully automated workflow that sequentially cleans, builds, and flashes using OpenOCD.

3.  **🚀🚀 Clean + Build + Flash (pyOCD)**: A fully automated workflow that sequentially cleans, builds, and flashes using pyOCD.

The detailed definitions for all tasks can be viewed and modified in the `.vscode/tasks.json` file.

## 🔬 Debugging

1.  **GDB Dependency**: The debugging feature relies on GDB from the **GNU Arm Embedded Toolchain**. Ensure this toolchain is installed and added to your system `PATH`.
2.  **Debug Configurations**: All debug configurations are pre-set in the `.vscode/launch.json` file.
3.  **Starting a Debug Session**:
      * Switch to the "Run and Debug" view in the VS Code sidebar.
      * From the top dropdown menu, select the configuration corresponding to your debugger: `openocd_CMSIS-DAP`, `openocd_ST-Link`, or `pyOCD`.
      * Press `F5` to start the debug session.

> **Note**: The `launch.json` also includes a configuration for `probe-rs`, but it is currently unstable and not recommended for debugging. However, flashing with `probe-rs` has been verified to work.

## ⚠️ Important Notes: DMA and Cache

To address **DMA** cache coherency issues when accessing peripherals, we have added a special memory section, `.buffer`, in the linker script (`.ld` file). This section is located in AXI SRAM (`0x24000000`).

When you need to define a buffer for DMA, use the following attributes to place it in this specified memory region:

```c
__attribute__((section(".buffer"))) __attribute__((aligned(4))) uint8_t my_dma_buffer[1024];
```

If you have the D-Cache enabled, you **must** manually clean the cache after the CPU modifies the data in this memory and before initiating a DMA transfer. This ensures that the peripheral can access the latest data:

```c
SCB_CleanDCache_by_Addr((uint32_t*)my_dma_buffer, sizeof(my_dma_buffer));
```

## 📁 Project Structure

```
STM32H743IIT6_template_ATfE/
├── App/                # Application and business logic code
├── Core/               # Core files generated by STM32CubeMX (Inc, Src)
├── Drivers/            # HAL library and CMSIS generated by STM32CubeMX
├── User_Drivers/       # User-defined driver code (e.g., for sensors, screens)
├── cmake/              # CMake configuration files
│   └── ATfE.cmake      # ATfE toolchain definition file
├── .vscode/            # VS Code editor configuration
│   ├── launch.json     # Debug configurations
│   └── tasks.json      # Build task definitions
├── .gitignore          # Git ignore file
├── CMakeLists.txt      # Main CMake configuration file
└── STM32H743IIT6.ioc   # STM32CubeMX project file
```
