# STM32H743IIT6 Project Template (Based on ATfE)

**English** | [中文](../README.md)

## 📋 Overview

This project uses the **Arm Toolchain for Embedded (ATfE)** compiler, which is customized by Arm based on LLVM and picolibc. The project initialization code is generated by STM32CubeMX, and by introducing the **CMake** build system and **Clangd** LSP, it achieves a consistent cross-platform development experience and efficient code indexing capabilities.

### ✨ Features

  * **Modern Toolchain**: Utilizes Clangd and ATfE.
  * **Cross-Platform Build Support**: Uses CMake and Ninja for consistent build experience across Windows, macOS, and Linux.
  * **VS Code Integration**: Pre-configured `.vscode/tasks.json` and `.vscode/launch.json` for convenient compilation, flashing, and debugging.
  * **Modular Project Structure**: Clear structure, easy to integrate business code, middleware, or RTOS.
  * **DMA Memory Management**: Defines dedicated RAM memory section (`.ram_section`) to address Cache coherency issues.

### 🔌 Hardware Platform

  * **Board**: FanKe Technology STM32H743IIT6 Minimum System Board.
  * **Display**: RGB interface TFT LCD screen.
  * **Pinout**: See the `.ioc` file in the project root directory (requires STM32CubeMX to view).

## 🏗️ Build & Deploy

### Workflow

The project integrates VS Code automated tasks (`Ctrl+Shift+B`) to simplify the development process.

Basic Tasks: Fundamental tasks that perform single operations.
1. **🔧 Configure**: Configure CMake environment. Usually automatically invoked by the `🔨 Build` task, no manual execution needed.
2. **🔨 Build**: Compile.
3. **🧹 Clean**: Clean build-generated files.
4. **📥 Flash (OpenOCD)**: Flash firmware to target device using OpenOCD (CMSIS-DAP). If you need to use other Link, please modify the task configuration. 
5. **📥 Flash (pyOCD)**: Flash firmware to target device using pyOCD (any Link supported by pyOCD).

Composite Workflows: Convenient workflows that execute multiple basic tasks in sequence.
1. **🧹-> 🔨**: Automatically execute clean and build steps in sequence.
2. **🔨-> 📥 (OpenOCD/pyOCD)**: Execute build and flash using OpenOCD or pyOCD in sequence.
3. **🧹-> 🔨 -> 📥 (OpenOCD/pyOCD)**: Execute clean, build, and flash using OpenOCD or pyOCD in sequence.

Detailed definitions of all tasks can be viewed and modified in the `.vscode/tasks.json` file.

### 🔨 Artifacts

By adding the following commands to the top-level CMakeLists.txt, the build system will automatically handle memory mapping and generate the files shown in the table.
```cmake
# Define paths for the output artifacts.
set(HEX_FILE ${CMAKE_BINARY_DIR}/${PROJECT_NAME}.hex)
# Define separate paths for internal and external flash.
set(INTERNAL_ELF_FILE ${CMAKE_BINARY_DIR}/internal_flash.elf)
set(EXTERNAL_BIN_FILE ${CMAKE_BINARY_DIR}/external_flash.bin)

# Add a post-build step to generate the.hex file from the.elf output.
add_custom_command(
    OUTPUT ${HEX_FILE}
    COMMAND ${CMAKE_OBJCOPY} -O ihex $<TARGET_FILE:${PROJECT_NAME}> ${HEX_FILE}
    DEPENDS ${PROJECT_NAME}
)

# Generate the.elf file for the internal flash.
add_custom_command(
    OUTPUT ${INTERNAL_ELF_FILE}
    COMMAND ${CMAKE_OBJCOPY} --remove-section=.qspi_section
            $<TARGET_FILE:${PROJECT_NAME}> ${INTERNAL_ELF_FILE}
    DEPENDS ${PROJECT_NAME}
)

# Generate the.bin file for the external QSPI flash.
add_custom_command(
    OUTPUT ${EXTERNAL_BIN_FILE}
    COMMAND ${CMAKE_OBJCOPY} -O binary --only-section=.qspi_section
            $<TARGET_FILE:${PROJECT_NAME}> ${EXTERNAL_BIN_FILE}
    DEPENDS ${PROJECT_NAME}
)

# Create a custom target to execute all file generation commands.  
add_custom_target(${PROJECT_NAME}_post_build ALL
    DEPENDS
        ${HEX_FILE}
        ${INTERNAL_ELF_FILE}
        ${EXTERNAL_BIN_FILE}
)
```
| File               | Description                                           |
| :----------------- | :---------------------------------------------------- |
| STM32H743IIT6.elf  | ELF file containing all data                          |
| STM32H743IIT6.hex  | HEX file containing all data                          |
| internal_flash.elf | ELF file containing only internal Flash data          |
| external_flash.bin | Pure binary file containing only external QSPI Flash data |

### 📥 External Flash Programming

For external QSPI Flash resources, it is recommended to use pyOCD with a customized download algorithm (FLM) for flashing:
```
pyocd flash -t stm32h743iitx build/Debug/internal_flash.elf build/Debug/external_flash.bin@0x90000000
```

**⚠️Warning:** Before using the `.flm` algorithm provided by this project, please ensure that the QSPI pin configuration of your target hardware is the same as this project. Otherwise, you need to prepare your own `.flm` algorithm.

## 🔬 Debugging

### Standard Debugging
1. **GDB Dependency**: The debugging functionality of this project depends on GDB from the **Arm GNU Toolchain**.
2. **Debug Configuration**: All debug configurations are preset in the `.vscode/launch.json` file.
3. **Start Debugging**:
   * Switch to the "Run and Debug" view in VS Code's sidebar.
   * Select the `openocd_CMSIS-DAP`, `openocd_ST-Link`, or `pyOCD` configuration to start debugging, depending on your debugger.

> **Note**: If external flash is used, pyOCD debugging is not available at this time. Please switch to OpenOCD or Ozone as described below.

### Ozone Debug

Ozone is a graphical debugger launched by Segger that can debug STM32 projects using JLink. If you wish to use other Links such as CMSIS-DAP, Ozone also provides a GDB option. After connecting to the MCU via OpenOCD or pyOCD, you can debug through GDB in Ozone. This feature currently requires applying for a certificate (URL: https://www.segger.com/purchase/licensing/license-request/).

## ⚠️ Memory Coherency & Cache

To ensure **DMA** accessibility, this project adds a new memory section `.ram_section` located in AXI SRAM (`0x24000000`) in the linker script (`.ld`).


Usage:
1. Declare data:
    ```c
    __attribute__(section(".ram_section"))) __attribute__((aligned(32))) uint8_t my_dma_buffer[1024];
    ```
2. Maintain coherency. If D-Cache is enabled, after the CPU modifies data in this region and before starting DMA transfer, you **must** perform cache cleaning:
    ```c
    SCB_CleanDCache_by_Addr((uint32_t*)my_dma_buffer, sizeof(my_dma_buffer));
    ```
